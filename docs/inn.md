# Noxac Pixel Dungeon 여관

## Windows에서 플레이

처음 실행하면 같은 게임 창의 캐릭터 생성 화면에서 닉네임, 직업, 머리색, 옷색, 헤어스타일, 장신구를 고르고 미리 본 뒤 입장한다. 선택을 저장하며, 여관에서 프로필을 다시 열어 바꿀 수 있다. 여관과 던전은 창 전체를 쓰고, 체력·행동력·퀵슬롯과 채팅은 게임 화면 위에 표시된다. 원정 메뉴, 배낭, 캐릭터 상태는 게임 안에서 연다.

- **동료 구함**을 선택하면 나무 팻말이 캐릭터 위에 나타난다. 같은 프로토콜을 쓰는 클라이언트끼리 자동으로 매칭하며, 다른 사람의 팻말을 클릭해 그 사람과 파티를 맺을 수 있다.
- **1인 원정 · 원본 ATB**는 여관 프로필로 원본 Shattered Pixel Dungeon 캠페인에 입장한다. 원본 층 생성, 몬스터, 장비, 아이템, 스킬을 사용하고 몬스터와 시간 효과는 입력을 기다리는 동안에도 진행된다.
- **길잡이 연습**은 같은 ATB 규칙의 1인 연습이다. 길잡이는 따라오고 가까운 적과 싸운다. Windows의 1인 원정과 연습은 오프라인에서도 실행된다.
- 연습 시작 방의 **허수아비**에는 평타와 화살을 쓸 수 있다. 근처에서는 이동에 행동력이 들고, 허수아비의 체력이 다하면 즉시 다시 찬다. **식량 상자** 칸을 밟으면 식량을 3개까지 채우고, **회복 도구** 칸을 밟으면 체력과 행동력을 회복한다. 쥐를 모두 잡은 뒤에도 연습할 수 있다.
- **원본 1인** 메뉴에서는 Shattered Pixel Dungeon의 기존 턴 규칙과 저장을 이용한다. 같은 직업의 가장 최근 일반 저장을 이어가며, 저장이 없으면 빈 슬롯에서 1층부터 시작한다. **저장하고 여관으로**, 영구 사망, 클리어 후 종료로 여관에 돌아온다.
- 여관 지도 위에서 마우스 휠로 확대·축소한다. 카메라는 내 캐릭터를 따라간다. 경비병, 여관주인, 노점상, 음유시인, 모험가를 클릭해 대화할 수 있다.
- **WASD**, 방향키 조합, 숫자패드로 8방향 이동한다. 여관과 던전은 첫 방향키 뒤 약 90ms 동안 두 번째 키를 대각선 조합으로 받을 수 있다. 숫자패드 대각선은 즉시 입력된다. 바닥을 클릭하거나 탭하면 경로를 찾아 이동한다. 적을 누르면 공격할 수 있는 칸까지 접근해 평타를 친다.
- 여관에서 방향키를 누르면 내 캐릭터가 먼저 움직이고 서버가 이동을 순서대로 확인한다. 이동 대기 중 짧게 누른 방향도 다음 한 칸에 반영된다.
- 대각선 목적지가 비어 있고 옆 두 칸 중 한 칸 이상이 열려 있으면 이동할 수 있다. 두 벽이 맞닿은 틈은 막힌다.
- 던전에서 **Q**는 평타, **1**은 활 조준, **2**는 식량이다. **F / I**는 배낭, **H**는 캐릭터 상태를 열고, **E**를 누른 뒤 칸을 선택하면 살펴볼 수 있다. **Space / 숫자패드 5 / Z**는 이동을 멈추고 기다린다. **R**로 멈춘 경로를 이어가고 **C**로 가까운 전리품을 향해 걷는다. **+ / −** 또는 휠로 확대·축소한다.
- 이동은 한 칸마다 0.18초 간격으로 이어지며, 평타 간격 0.8초 중에도 이동할 수 있다. 활을 조준한 뒤 쏠 칸을 고른다. 여관의 **아군 피해**는 파티장 설정을 따르며 시작값은 꺼짐이다.
- 적이 떨어뜨린 아이템은 두 화면에 같이 표시된다. 먼저 아이템 칸에 들어간 사람이 줍는다. 소탕 후에도 움직여 남은 아이템을 주울 수 있다.
- 여관과 파티 던전에서 **F1**로 반투명 조작 도움말을 열고 닫는다.
- 여관, 파티 원정, 길잡이 연습에서 **Enter**로 채팅 입력을 열고 다시 **Enter**를 눌러 전송한다. **Esc**로 입력에서 나올 수 있다. 보낸 말은 캐릭터 위에 잠시 표시되며, 채팅창을 스크롤해 다시 볼 수 있다.

## 브라우저에서 플레이

[웹 여관](https://noxac-pixel-dungeon-inn.kimyc3825.chatgpt.site/play/)에서 닉네임과 외관을 고르고 **입장**을 누른다. 최신 브라우저판과 Windows 0.15.1은 같은 여관과 매칭을 사용한다. 어느 클라이언트든 파티장이나 참가자가 될 수 있다.

브라우저에서도 **1인 원정 · 원본 ATB**를 플레이한다. **동료 찾기**나 모험가의 팻말은 2인 ATB 시험 던전으로 연결된다. 가까운 주민과는 **F** 또는 클릭으로 대화한다. 2인 원정 중에는 파티장이 게임 창이나 브라우저 탭을 열어 둔다.

웹 여관을 열면 브라우저가 ATB 던전 코드와 에셋을 백그라운드에서 준비한다. 입장할 때 버전을 다시 확인하고, 캐시에 있는 같은 버전은 재사용한다. 원정을 준비하는 동안 로딩 문구가 표시된다.

**원본 1인 저장**은 원본 4.0.2 Java 엔진의 브라우저 빌드를 연다. 같은 직업의 저장은 이 사이트의 브라우저 저장소에서 이어간다. 게임 중 저장 후 나가거나, 영구 사망하거나, 클리어 화면에서 종료하면 같은 탭의 여관으로 돌아온다.

## 원본 던전의 ATB

원본의 한 턴을 0.8초에 맞추어 진행한다. 행동력은 최대 10이고, 사용 뒤 0.5초가 지나면 0.8초에 1씩 회복한다. 적이 보이는 중의 한 칸 이동과 표준 평타는 행동력 1을 쓴다. 이동 간격은 기본 0.18초에서 이동속도의 영향을 받으며, 다음 평타까지 걸리는 시간은 원본 무기와 상태 효과가 정한다. 배낭처럼 원본 게임의 창을 여는 동안 시간과 행동력 회복을 멈춘다.

원본 ATB에서는 공격 판정이나 피격이 누르고 있는 방향키와 대기 중인 한 칸 이동을 지우지 않는다. 행동력이 부족하면 회복된 뒤 이동한다. 몬스터가 나타나거나 공격하면 긴 자동 이동은 멈춘다.

원본 ATB는 별도의 저장 슬롯에 층, 장비, 진행과 행동력을 저장한다. 게임 메뉴의 **저장하고 여관으로**로 나간 뒤 같은 직업을 골라 이어간다. 기존 턴제 저장은 **원본 1인 저장**으로 연다.

## 입장 프로필과 외관 추가

여관, 파티 원정, 길잡이 연습, 1인 원정에 같은 프로필 외관을 사용한다. 전사, 마법사, 도적, 사냥꾼, 결투자, 성직자의 원본 실루엣과 이동·공격 프레임을 바탕으로 머리와 옷, 장식 레이어를 합성한다. 원본 1인 게임에서 새로 시작할 때는 여관에서 고른 직업의 장비와 능력을 사용한다. 원본 저장 공간이 가득 차고 같은 직업의 저장이 없으면 이어갈 저장을 고르는 창이 열린다.

외관 옵션과 픽셀 패턴은 `inn-server/scripts/generate-avatars.py`에서 관리한다. Python 3과 Pillow로 이 스크립트를 실행하면 두 클라이언트가 공유하는 직업별 PNG와 카탈로그가 다시 생성된다. 카탈로그의 각 항목은 ID와 표시 이름을 갖는다. 이미 저장한 프로필을 위해 기존 ID는 유지한다.

아틀라스는 각 행에 12×15픽셀 프레임 18개를 갖는다. 기본 그림, 옷색, 머리 모양과 머리색 조합, 장신구 순으로 행을 배치한다. 입장과 매칭 링크는 옵션 ID만 보내며, 웹과 Windows가 같은 레이어 순서로 그린다.

## 던전 테마

시험 던전의 여관 테마는 **하수도** 또는 **버려진 감옥**이다. 길잡이 훈련에는 내가 고른 테마를, 2인 원정에는 파티장이 고른 테마를 적용한다. 하수도와 감옥에서는 벽 북쪽을 지날 때 벽의 윗부분이 캐릭터 하단을 가린다.

하수도는 익숙한 고정 맵으로 시작한다. 감옥은 원정 시드로 방 여섯 개의 크기와 배치를 정한 뒤 순환 복도와 가지 복도를 판다. 두 사람은 같은 시작 방에 등장하고 쥐 두 마리는 떨어진 방에 배치된다. 파티장이 완성된 맵과 테마를 두 사람에게 공유한다.

원본의 [RegularLevel](https://github.com/00-Evan/shattered-pixel-dungeon/blob/v4.0.2/core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/levels/RegularLevel.java)과 [LoopBuilder](https://github.com/00-Evan/shattered-pixel-dungeon/blob/v4.0.2/core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/levels/builders/LoopBuilder.java)를 참고해 방 준비, 연결, 타일 채우기 순서로 구성했다. Windows의 `DungeonLayout.java`와 웹의 `layout.mjs`에 생성 규칙이 있다. 테마를 추가할 때는 이 규칙의 방 배치와 스폰, 해당 타일 시트, 여관의 테마 선택을 연결한다.

### 행동력

| 행동 | 원본 1인 게임 기본 코스트 | ATB 원정 행동력 |
| --- | --- | --- |
| 이동 | 이동속도 1에서 1턴 | 전투 중 1, 전투 밖 자유 이동 |
| 평타 | 표준 무기 1턴 | 1 |
| 활 | 장비와 특성에 따라 달라짐 | 2 |
| 일반 식량 | 3턴 | 3 |

행동력은 캐릭터마다 최대 10이다. 행동력을 쓴 뒤 0.5초가 지나면 회복이 시작되고, 0.8초에 1만큼 찬다. 식량은 각 플레이어가 하나 들고 시작하고, 주운 식량도 먹을 수 있다. 하수도 시험 맵의 식량은 HP를 최대 6 회복한다. 쥐 추격 간격은 0.38초, 공격 간격은 0.8초다.

원본의 이동은 `Hero`에서 `1 / speed()`, 표준 평타는 `Hero.attackDelay()`와 `Weapon.delayFactor()`, 일반 식량은 `Food.TIME_TO_EAT`를 기준으로 비교했다. 원본의 무기별 공격 속도와 식사 시간을 바꾸는 특성은 원본 1인 게임에 적용된다. ATB 원정과 연습의 행동력과 전리품은 해당 원정 안에서 관리한다.

### 공격과 아군 피해

평타는 선택한 캐릭터의 현재 사거리를 판정한다. 공격 전에 대상이 사거리를 벗어나거나 벽에 막히면 이유를 표시하고 행동력과 새 쿨타임은 쓰지 않는다.

화살은 조준한 칸까지 최대 다섯 칸을 이동한다. 한 칸에 0.1초가 걸리며 평타와 0.8초 쿨타임을 공유한다. 첫 벽이나 살아 있는 개체에서 멈춘다. 빈 목표 칸까지 도달하면 빗나가고, 발사에 쓴 행동력과 쿨타임은 유지된다.

아군 피해가 꺼져 있으면 화살을 가로막은 파티원이나 길잡이는 피해를 받지 않는다. 켜져 있으면 피해를 받고, 그 아군을 명시적으로 클릭해 평타를 쓸 수도 있다. Q는 가까운 적을 선택한다.

### 작전타임

파티 원정과 길잡이 훈련 중 **작전타임** 버튼 또는 **P**를 누르면 화면이 회색으로 바뀌고 게임 시간이 최대 60초 멈춘다. 적 행동, 이동, 평타, 식량 사용과 행동력 회복이 멈춘다. 예약한 행동은 남은 시간을 보존한다.

어느 파티원이든 작전타임을 시작하거나 다시 눌러 해제할 수 있다. 해제하거나 60초가 지나면 파티 공용 쿨타임 60초가 시작된다. 작전타임 중에는 채팅을 사용할 수 있고, 배낭과 파티원 상태창은 조회 전용이다.

## 빌드

[원본 업데이트 검토 절차](upstream-update.md)

Windows x64에서 JDK 21을 지정한 뒤 저장소 루트에서 실행한다.

```powershell
.\gradlew.bat -p inn-client packageWindows
```

출력은 `inn-client/build/jpackage/0.15.1/NoxacPixelDungeon/NoxacPixelDungeon.exe`다. 실행 폴더에 Java와 게임 에셋이 포함된다.

원본 브라우저판은 저장소 루트에서 `.\gradlew.bat -PwebOnly html:dist`로 빌드한다. 결과는 `html/build/dist/web`에 생성된다.

기본 서버는 [여관 운영](https://noxac-pixel-dungeon-inn.kimyc3825.chatgpt.site)이다. 로컬 개발에서는 `NOXAC_INN_URL`을 `http://127.0.0.1:8787`로 설정한다.

## 네트워크와 전투

Sites Worker와 관리형 D1이 여관, 매칭, 세션 인증, WebRTC 연결 정보 교환을 맡는다. 0.9 및 0.10 계열 클라이언트는 여관 입장 시 `dungeonProtocol: 7`을 보낸다. 0.8 계열은 프로토콜 6, 0.6 및 0.7 계열은 프로토콜 5, 0.5 계열은 프로토콜 4, 0.4 계열은 기존 V3 던전 API를 사용한다.

파티장의 클라이언트 한 곳에서 이동, ATB, 적 행동, 피해와 전리품을 확정한다. Windows와 브라우저의 파티장이 같은 규칙과 프로토콜을 사용한다. 참여자는 입력마다 번호를 붙인다. 파티장은 처리한 번호를 기록하고, 두 사람에게 같은 좌표·체력·전리품 목록을 보낸다. 처치당 하나의 ID로 드롭을 기록하고 먼저 들어간 플레이어에게 획득을 귀속한다. 내 이동과 평타 준비 동작은 즉시 시작하며, 위치를 파티장의 판정에 맞춰 보정한다.

던전의 데이터는 WebRTC로 직접 보내고, 직접 연결 준비 중이거나 사용할 수 없으면 Sites가 메시지를 중계한다. 던전 상단에서 현재 연결 방식을 확인할 수 있다. 전투 계산은 중계 중에도 파티장 클라이언트에서 실행된다. 파티장 이탈 시 해당 원정은 종료된다. 다른 연결 환경을 로컬에서 재현할 때는 Java 옵션 `-Dnoxac.inn.relayOnly=true`로 중계를 강제할 수 있다.

```powershell
Set-Location inn-server
npm ci
npm test
npm run dev
```

여관은 `/api/v2/inn/session`, `/sync`, `/move`, `/chat`, `/drink`, `/match`를 사용한다. `/match` 요청의 `queued`는 매칭 신청 또는 취소이며, 신청할 때 `targetId`를 보내면 그 팻말의 상대를 지정한다.

두 참가자는 여관의 토큰과 `matchId`로 `POST /api/v4/link/enter`를 호출한다. 이후 `/api/v4/link/sync`, `/signal`, `/relay`, `/leave`에는 같은 링크 `id`를 보낸다. `/signal`은 `type`과 `sdp`를, `/relay`는 증가하는 `seq`와 최대 24 KiB의 `message`를 받는다. 중계는 송신자별로 최신 메시지 한 건을 유지한다. 인게임 입력은 `move`, `attack`, `shoot`, `eat`, `pause`, `chat`이며, 참가자는 마지막 확인 이후 입력을 순서대로 묶어 보낸다. 파티장은 진행 중인 화살, 최근 공격 결과, 작전타임 시각, 채팅, 처리한 입력 번호를 상태와 함께 돌려준다.

배포에는 `inn-server`의 Worker 소스와 D1 마이그레이션을 사용한다. `GET /api/v4/health`로 연결 API의 준비 상태를 확인할 수 있다.
