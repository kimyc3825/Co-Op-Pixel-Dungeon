# Co-Op-Pixel-Dungeon 여관

## Windows와 브라우저에서 플레이

여관 프로필에서 닉네임, 직업과 외관을 고릅니다. Windows는 같은 게임 창에서 원정에 들어가고 웹은 여관 화면 안에서 원본 엔진을 엽니다.

- **1인 원정**은 Shattered Pixel Dungeon 캠페인 1층에서 시작합니다. 여관에서 선택한 직업, 장비와 외관을 사용하고 원본과 같은 턴제로 진행합니다. 플레이어가 행동하지 않으면 던전 시간도 멈춥니다.
- **동료 찾기 · 2인 원정**은 매칭된 두 사람이 파티장의 원본 캠페인 1층에서 출발합니다. 파티장이 맵과 전투를 판정하고, 동료의 이동·평타·대기와 적의 피해를 같은 원본 던전에 적용합니다. 시간은 두 사람이 행동할 때만 흐릅니다. 동료도 원본 맵과 몬스터, 전리품을 보고 파티장을 따라 다음 층으로 이동합니다. 동료의 독립 장비·가방·스킬은 이후 작업 범위입니다.
- **길잡이 연습**은 원정 모드의 연습 전용 층입니다. 길잡이와 함께 원본 이동과 전투를 연습합니다. 허수아비는 쓰러져도 다시 일어납니다. 식량 상자와 회복 도구를 클릭해 식량을 받거나 체력과 허기를 회복합니다. 연습은 원정 저장과 기록에 반영되지 않습니다.
- **원본 1인 저장**에서는 기존 턴제 저장을 엽니다. 원정에서 철수하면 현재 원정이 끝나고, 다음 원정은 1층에서 시작합니다.
- 여관에서는 나무 팻말을 눌러 모집 중인 상대에게 바로 참가할 수 있습니다. **Enter**로 채팅을 열고, 마우스 휠로 확대·축소합니다.

브라우저는 여관에 입장하면 원본 게임과 시작 에셋을 미리 받습니다. 원정에 입장할 때 같은 버전의 다운로드를 이어 쓰고, 캐시된 에셋을 재사용합니다.

## 입장 프로필과 외관 추가

여관, 파티 원정, 길잡이 연습, 1인 원정에 같은 프로필 외관을 사용한다. 전사, 마법사, 도적, 사냥꾼, 결투자, 성직자의 원본 실루엣과 이동·공격 프레임을 바탕으로 머리와 옷, 장식 레이어를 합성한다. 원본 1인 게임에서 새로 시작할 때는 여관에서 고른 직업의 장비와 능력을 사용한다. 원본 저장 공간이 가득 차고 같은 직업의 저장이 없으면 이어갈 저장을 고르는 창이 열린다.

외관 옵션과 픽셀 패턴은 `web-client/scripts/generate-avatars.py`에서 관리합니다. Python 3과 Pillow로 스크립트를 실행하면 두 클라이언트가 공유하는 직업별 PNG와 카탈로그가 생성됩니다. 저장된 프로필이 동작하도록 카탈로그의 기존 ID를 유지합니다.

아틀라스는 각 행에 12×15픽셀 프레임 18개를 갖는다. 기본 그림, 옷색, 머리 모양과 머리색 조합, 장신구 순으로 행을 배치한다. 입장과 매칭 링크는 옵션 ID만 보내며, 웹과 Windows가 같은 레이어 순서로 그린다.

## 여관 배경 작업

웹과 Windows는 같은 [inn-layout.json](../web-client/play/assets/inn-layout.json)을 사용합니다. `map`은 여관의 26×17 칸 배치입니다. 좌표는 왼쪽 위 `(0, 0)`부터 시작합니다.

| 문자 | 용도 | 이동 가능 |
| --- | --- | --- |
| `#` | 벽 | × |
| `.` | 바닥 | ○ |
| `B` | 카운터 또는 벽난로 | × |
| `T` | 탁자 | × |
| `N` | NPC 자리 | × |
| `D` | 출입구 바닥 | ○ |

같은 파일에서 입장 좌표 `spawns`, 원정 출입구 범위 `expeditionGate`, NPC의 위치와 대사를 편집할 수 있습니다. 입장 좌표는 `.` 또는 `D` 칸에, NPC 좌표는 `N` 칸에 둡니다.

웹의 바닥, 가구, 조명은 [inn-decor.mjs](../web-client/play/inn-decor.mjs)에서 그립니다. Windows판의 같은 작업은 [NativeInnBoard.java](../inn-client/src/main/java/com/noxac/pixeldungeon/inn/NativeInnBoard.java)의 `rebuildFloor`, `paintTerrain`, `paintHallFeatures`에서 합니다. 새 배치로 옮기는 벽난로, 바, 원정 출입구의 그림도 여기에서 조정합니다.

현재 배치의 여관 홀은 미리 그린 그림 한 장을 씁니다. 배경, 불꽃 애니메이션, NPC 그림은 `web-client/scripts/generate-inn.mjs`가 그리며, 저장소 루트에서 `node web-client/scripts/generate-inn.mjs`를 실행하면 두 클라이언트가 함께 쓰는 `inn-hall.png`, `inn-hall-fx.png`, `inn-npcs.png`와 `inn-hall.mjs`가 다시 생성됩니다. 이 그림은 `map`이 스크립트의 맵과 정확히 같을 때만 쓰이고, 다르면 위 코드로 타일을 그립니다. 칸 배치를 바꾸면 스크립트의 `MAP`과 `NativeInnBoard.java`의 `HALL_MAP`, `HALL_FX`도 같은 값으로 맞춥니다.

저장소 루트에서 다음 명령을 실행한 뒤 [여관 전체 지도 미리보기](http://127.0.0.1:8000/preview/)를 엽니다. Python 3과 브라우저가 필요하며, 공개 파일로 실제 웹 렌더러를 실행합니다.

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory web-client
```

여관의 벽과 가구 충돌은 각 클라이언트가 판정합니다. 칸 배치나 NPC ID·좌표가 달라지면 별도의 여관으로 접속합니다. 같은 공간에서 만나려면 양쪽에 같은 배치를 사용하세요. 배경 그림, 외관 에셋, 대사 변경은 여관을 나누지 않습니다.

## 던전과 턴

원정은 원본 캠페인의 층 생성과 테마를 따릅니다. 길잡이 연습은 원본 타일과 캐릭터를 사용하는 고정 연습 층입니다.

던전 시간은 플레이어가 행동할 때만 흐릅니다. 실제 시간은 게임 시간에 영향을 주지 않으므로, 아무도 행동하지 않는 동안에는 허기, 체력 회복과 상태 효과도 진행되지 않습니다. 모든 행동은 원본과 같은 턴 시간을 씁니다. 한 칸 이동은 이동 속도에 따라, 평타는 공격 간격에 따라, 아이템과 직업 기술은 각 원본 행동의 시간만큼 걸립니다.

- **1인 원정**은 원본 턴제와 같습니다. 입력을 기다리는 동안 던전이 멈추고, 생각할 시간에 제한이 없습니다.
- **파티**에서는 파티장과 동료가 같은 행동 순서를 공유합니다. 몬스터는 원본 순서대로 행동하고, 차례가 된 플레이어가 입력할 때까지 던전이 기다립니다.
- 두 사람 모두 입력을 기다리고 있으면 던전은 원본처럼 멈춥니다. 한 사람이 먼저 행동해 앞서 나가면, 남은 사람의 상태에 따라 진행이 달라집니다.
  - 전투 중이 아니면 기다리지 않습니다. 앞선 사람의 행동만큼 던전이 진행되고, 기다리지 않은 사람은 행동을 잃지 않으며 다음 입력을 현재 시점에 실행합니다.
  - 전투 중이면 5초 동안 입력을 기다립니다. 입력하지 않으면 자동으로 1턴을 대기하고 머리 위에 "대기"가 표시됩니다. 입력 없이 두 번 연속 자동 대기하면, 다시 입력할 때까지 대기 시간이 0.5초로 줄어듭니다.
  - 전투 중이란 살아 있는 적이 그 플레이어를 추적하고 있거나, 깨어 있는 적이 그 플레이어의 시야 안에 있는 상태입니다. 두 사람의 전투 상태는 따로 판정합니다.
- 대기 시간은 던전이 실제로 그 플레이어를 기다리는 동안에만 줄고, 파티장의 게임이 일시 정지되면 멈춥니다. 내 차례를 기다리면 화면 위쪽에 남은 시간이, 동료를 기다리면 "동료를 기다리는 중"과 동료의 남은 시간이 표시됩니다.
- 시간을 멈추는 효과(시간군주의 모래시계, 신속엉겅퀴)를 쓰는 동안에는 원본처럼 그 플레이어만 행동하고 던전은 기다립니다.
- 몬스터의 발견 판정은 원본처럼 몬스터 자신의 차례에 합니다. 동료도 파티장과 같은 조건으로 발견됩니다.
- 파티 동료는 방향키 또는 WASD로 이동하고, 적을 클릭하거나 가까운 적에게 **Q**를 눌러 평타를 칩니다. **Space**나 대기 버튼으로 1턴을 대기하고, **Esc**로 여관에 돌아갑니다.

## 빌드

[원본 업데이트 검토 절차](upstream-update.md)

Windows x64에서 JDK 21을 지정한 뒤 저장소 루트에서 실행한다.

```powershell
.\gradlew.bat -p inn-client packageWindows
```

출력은 `inn-client/build/jpackage/0.16.10/NoxacPixelDungeon/NoxacPixelDungeon.exe`입니다. 실행 폴더에 Java와 게임 에셋이 포함됩니다.

원본 브라우저판은 저장소 루트에서 `.\gradlew.bat -PwebOnly html:dist`로 빌드한다. 결과는 `html/build/dist/web`에 생성된다.

기본 서버는 [여관 운영](https://co-op-pixel-dungeon.kimyc3825.chatgpt.site)입니다. 로컬 개발에서는 `NOXAC_INN_URL`로 서버 주소를 지정할 수 있습니다.

공개 저장소의 `main`에 푸시하면 GitHub Actions가 웹 여관과 던전 런타임을 빌드해 Sites에 게시합니다. 브라우저에서 제공하는 여관의 소스는 `web-client/play`에 있습니다.

[웹 배포 실행 기록](https://github.com/kimyc3825/Co-Op-Pixel-Dungeon/actions/workflows/deploy-web.yml)에서 배포가 완료됐는지 확인할 수 있습니다. Windows 패키지는 [GitHub Releases](https://github.com/kimyc3825/Co-Op-Pixel-Dungeon/releases)에 게시합니다.

## 네트워크와 전투

새 클라이언트는 여관 입장 시 배치 ID와 시작 좌표를 보냅니다. Sites Worker와 D1이 위치, 채팅, NPC 상호작용 알림과 프로필 옵션 ID를 중계하고 파티 매칭, 링크 인증과 WebRTC 시그널링을 맡습니다. 한 여관 안에서 같은 던전 프로토콜의 참가자끼리 매칭합니다. 구버전은 기본 배치를 사용하는 새 클라이언트와 같은 여관에 접속합니다. Worker 소스와 운영 설정은 별도의 비공개 저장소에서 관리합니다.

파티장의 원본 엔진이 층 생성, 충돌, 적 행동, 피해와 전리품을 한 번 처리합니다. 동료는 층 번호와 순서 번호가 있는 이동·평타 명령을 보내고, 파티장은 확인 번호와 최신 탐색 지형, 위치·체력·행동력, 표시할 전리품을 공유합니다. 층이 바뀌면 이전 층의 명령을 버립니다. 전송은 WebRTC 직접 연결을 사용하며 필요할 때 Worker가 중계합니다. Java 옵션 `-Dnoxac.inn.relayOnly=true`로 개발 중 중계를 시험할 수 있습니다.

동료가 쓰러지면 해당 원정에서 쓰러진 상태를 유지합니다. 어느 쪽이 연결을 종료하면 해당 파티 원정을 종료합니다.

여관은 `/api/v2/inn`, 연결은 `/api/v4/link`를 사용합니다. `GET /api/v4/health`로 연결 API의 준비 상태를 확인할 수 있습니다.
